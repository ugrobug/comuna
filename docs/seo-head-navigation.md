# Метаданные статьи при переходе в сообщество

У статьи, сообщества, профиля и информационной страницы за индивидуальные метаданные отвечает компонент страницы. Общий шаблон выводит резервное описание на страницах, где оно требуется. В серверном HTML теги остаются внутри границ, которыми Svelte отмечает владельца каждого фрагмента. При уходе со статьи Svelte удаляет её разметку, включая BlogPosting. Сборка SvelteKit выводит теги превью перед CSS.

Сервер передаёт корневому шаблону языковое предпочтение пользователя или браузера отдельно от языка конкретного URL. При каждом переходе шаблон применяет префикс нового URL либо возвращается к этому предпочтению. Для этого достаточно данных первого запроса.

PostMetaDescription выбирает описание редактора, первый непустой абзац или заголовок, либо обычный текст для старых публикаций. HTML-сущности декодируются до ограничения длины в 200 символов. Одно текстовое значение используется для HTML, Open Graph, Twitter и описания статьи в JSON-LD. Экранирование при выводе выполняют Svelte и сериализатор JSON-LD.

## Как проверить

Из корня проекта:

```sh
node_modules/.bin/vitest run src/hooks.server.test.ts src/lib/PostMetaDescription.test.ts src/lib/seoJsonLd.test.ts
ADAPTER=node npm run build
node --test --test-force-exit tests/seo-head.integration.mjs
```

Интеграционная проверка использует собранный сервер и тестовые ответы API для RU-, EN- и ES-версий статьи, сообщества, профиля и страницы «О проекте». Она сверяет значения и количество тегов, взаимные языковые ссылки и положение картинки превью относительно CSS.

Для проверки навигации открыть намеренно закрытую ES-статью, перейти по ссылке сообщества, нажать «Назад», затем «Вперёд». Сравнить метаданные каждого состояния с прямым открытием того же URL с теми же языковыми настройками. У сообщества должен быть собственный canonical и отсутствовать BlogPosting, у ES-статьи должен восстанавливаться noindex. Повторить для индексируемой RU-статьи и с авторизацией.

## Стоимость и проверка перед выпуском

Локальный замер 25 ноября 2026 года, Node 25.2.1, один последовательный запрос за раз, без кеша ответа. На одинаковой ES-статье после пяти прогревочных запросов выполнено по 60 измерений полного формирования HTML для каждой версии и роли. API заменён локальными ответами. SQL в этом эксперименте не выполнялся.

| Сценарий | Медиана до → после | HTML до → после | Обращения к API до → после |
| --- | --- | --- | --- |
| Гость | 1,12 → 1,17 мс | 46 311 → 46 245 байт | 1 → 1 |
| Тестовая авторизация | 1,14 → 1,04 мс | 46 433 → 46 367 байт | 2 → 2 |

Стоимость формирования описания зависит от размера текста одной статьи. Количество публикаций в базе на этот шаг не влияет. При десятикратном росте трафика число вызовов рендера растёт пропорционально запросам без кеша. Изменение не добавляет хранения, фоновых работ и обращений к базе. Замеры не включают сеть, реальные проверки доступа, отрисовку экрана и нагрузку production. После выпуска повторить переход на рабочем сайте. Откат — вернуть предыдущую версию фронтенда. Миграций нет.

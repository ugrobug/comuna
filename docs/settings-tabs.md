# Вкладки настроек сайта

Страница `/settings` использует тот же `ComunSettingsTabs`, что и настройки
сообщества. Разделы: «О себе» (профиль, Telegram/MAX, удаление), «Уведомления»,
«Интерфейс» (тема, язык, открытие постов), «Лента» (стартовая лента и фильтры).
Существующие операции сохранения, импорта, экспорта и сброса сохранены.

`SettingsNavigation` отвечает за допустимые вкладки, URL и совместимость старых
ссылок с якорями. Компонент страницы адаптирует навигацию к SvelteKit shallow
routing: выбранная вкладка хранится в query и PageState. Переключение не запускает
повторную загрузку маршрута. Работают обновление страницы, Назад/Вперёд,
стрелки клавиатуры и Home/End. По умолчанию у вошедшего пользователя открывается
профиль, у гостя — интерфейс; персональные вкладки гостю сообщают о необходимости входа.

Содержимое создаётся при первом посещении вкладки, затем скрывается через hidden.
Это сохраняет черновик профиля и состояние асинхронного сохранения уведомлений.
Не больше четырёх панелей на страницу, без глобального кеша и новых зависимостей.
Уведомления и словарь тегов загружаются при первом открытии соответствующей вкладки;
MAX — при раскрытии секции. Первому экрану нужны только уже существующие данные
аккаунта и локальные настройки. Синхронизация формы явно зависит от siteUser,
поэтому вход непосредственно на странице настроек заполняет поля профиля.

## Проверки 2026-10-05

- 15 тестов SettingsNavigation: все вкладки, дефолты, старые якоря, некорректные
  значения, сохранение других query-параметров.
- В браузере: гость и владелец, все вкладки, черновик после переключений,
  Назад/Вперёд, обновление URL, `/settings#notifications`, клавиатура, экран 390×844.
  Горизонтального переполнения страницы профиля нет (ширина документа = viewport).
- build и Django check прошли. Общий svelte-check: прежние 20 ошибок и 4 предупреждения
  в 12 других файлах; затронутые этой правкой файлы ошибок не добавили.

Локально Vite dev + Django/PostgreSQL, пустой тестовый аккаунт, без кеша ответа:
раньше первый экран владельца запрашивал notifications/settings, tags и max/account;
после изменения при открытии профиля эти три запроса отсутствуют. В отдельном проходе
«О себе → Уведомления → Лента → Уведомления → Лента → О себе» повторных запросов
уведомлений не было, tags запрошен один раз, MAX не запрашивался. На тестовом наборе
отложенные ответы составляли 11360, 24 и 106 байт соответственно.

Сравнение гостевого HTML на одном localhost-сервере: ожидание применения исходников,
2 прогрева, затем 5 последовательных чтений каждой версии. До: TTFB
14.01/24.02/6.11/6.12/5.16 мс, 206594 байт; после:
17.56/14.99/10.26/5.85/5.44 мс, 197312 байт. Это небольшая dev-выборка с шумом,
не подтверждение ускорения TTFB, p95 или LCP. Подтверждённое сокращение — размер
первой разметки и отложенные сетевые запросы. Время SQL отдельно не измерялось;
backend/ORM этой правкой не меняется. LCP/INP и конкурентная нагрузка на staging
не проверялись; production-замеры выполняются после отдельного релиза.

При росте числа пользователей в 10 раз работа одной страницы остаётся ограниченной
четырьмя вкладками; новая логика не обходит пользователей/посты. Существующий запрос
словаря тегов остаётся прежним и не оптимизируется этой задачей. Новых сервисов,
индексов и миграций именно для вкладок нет. Откат — возврат страницы, навигации,
типов, подписей и изменений общего компонента вкладок; данные настроек совместимы.

# О себе на странице автора

`SiteUserProfile.bio` — необязательный обычный текст до 2000 символов.
Миграция 0181 добавляет поле с пустым значением; существующие записи совместимы.
Индексы не нужны: профиль читается по существующему уникальному user_id.

`SiteProfileUpdateService` отвечает за валидацию и сохранение редактируемых полей;
HTTP view и совместимый `_update_site_profile` остаются адаптерами. Описание
нормализует переводы строк, не преобразует HTML в разметку, допускает очистку.
Отсутствующее поле не меняет значение (старые web/mobile клиенты совместимы).
Удаление аккаунта очищает bio; слияние использует описание исходного аккаунта
только при пустом описании целевого.

Поле в настройках отправляется существующим PATCH /api/auth/me/.
Публичный GET /api/site-users/:id/profile/ возвращает его в существующем user DTO;
select_related уже загружает профиль, дополнительных запросов нет.
Страница /id:id показывает блок только при непустом bio активного пользователя.
Svelte выводит экранированный текст, сохраняет абзацы и переносит длинные слова.
Нет редактора, сторонних ресурсов, новых HTTP-запросов или пакетов JS.

## Кеш и выпуск

API профиля возвращает private/no-store, существующий SSR handleFetch передаёт
это ограничение в HTML. Иначе гостевой nginx HTML-кеш мог показывать прежнюю
биографию до 10 минут, а API — до 30 секунд. Теперь каждое открытие обращается
к существующему запросу профиля. Это осознанный обмен кеш-попаданий на актуальность
персональных данных; прежняя стоимость постов/сообществ в профиле не оптимизировалась.
При росте посещаемости в 10 раз растёт число чтений; работа именно bio остаётся
одним полем до 2000 символов, без обхода других пользователей и без новых сервисов.

Перед выпуском применить миграцию до старта кода, который читает новый столбец.
При первом выпуске нужно убрать старые ответы именно /id:id (включая локализованные
пути, если они есть) и /api/site-users/:id/profile/ из nginx/CDN-кеша: новые заголовки
не удаляют уже закешированные страницы. Общий кеш ради измерения не очищать.
После выпуска проверить анонимное изменение/очистку профиля на прогретых страницах.
Откат кода допускается без удаления столбца; обратная миграция удалит описания,
поэтому для безопасного отката столбец оставить.

## Проверки

Локально: PostgreSQL, Django test client, пользователь без постов/сообществ,
одинаковые сценарии до/после, по 6 последовательных вызовов. Ниже медиана последних
5 после первого прогрева. Кеша ответа нет, данные/соединение прогреты; это не p95
и не нагрузочный тест. Миллисекунды SQL имеют ограниченную точность Django.

| Сценарий | Время мс до → после | SQL до → после | SQL мс до → после | JSON байт до → после |
|---|---|---|---|---|
| Гость, пустое описание | 5.99 → 5.98 | 5 → 5 | 3.0 → 3.0 | 282 → 295 |
| Владелец, пустое описание | 6.89 → 7.17 | 6 → 6 | 3.0 → 4.0 | 282 → 295 |
| Сохранение имени (старый клиент) | 4.53 → 4.45 | 9 → 9 | 1.0 → 0.0 | 418 → 431 |

- read_guest_full: 5.60 мс, 5 SQL, 12294 байт JSON (2000 кириллических символов, стандартное JSON escaping).
- read_owner_full: 6.61 мс, 6 SQL, 12294 байт JSON (2000 кириллических символов, стандартное JSON escaping).
- write_full: 4.88 мс, 9 SQL, 12430 байт JSON (2000 кириллических символов, стандартное JSON escaping).

В браузере проверены сохранение через настройки, чтение после навигации, экранирование
`<script>`, абзацы и формы/карточка на ширине 390 px. Локальный Vite + Django:
HTML профиля гостя 31.4–34.7 мс, API через Vite 24.0–38.5 мс (3 запроса каждого).
Это dev-замеры HTTP, не пользовательские LCP/INP. API и HTML отдают no-store.

32 постоянных backend-теста прошли до добавления проверки кеша; отдельный итоговый
набор bio — 8 тестов, включая кеш (33 уникальных постоянных теста суммарно).
Временный тест сравнения производительности также прошёл. npm run build, Django check
и makemigrations --check прошли. Общий npm run check сообщает 20 ошибок в 12 других
файлах; в изменённых компонентах ошибок нет. Проверки staging, конкурентной нагрузки,
профилей с большим количеством постов и production не выполнялись; выигрыш LCP или
p95 не заявляется. Миграция применена только к локальной тестовой базе.

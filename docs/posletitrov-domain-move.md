# posletitrov.ru: уход с WordPress / Beget-хостинга

Дата: 26 октября 2026. Регистрация домена остаётся в Beget; владелец меняет
делегирование на NS Jino отдельно, после проверки HTTPS и DNS-зоны.

## Что переносится

Два пользовательских экспорта содержат 7071 точечную запись и 7 правил архивов.
После нормализации: 7028 уникальных путей, 2 одинаковых дубля, 41 конфликт.
Все конфликты — старое назначение тега на статью против нового назначения
на страницу тега. Выбрана страница тега; действующий WordPress подтвердил
такое поведение на `/tag/ajta/` и `/tag/anora/`. Полный отчёт и SHA256 исходных
экспортов: `posletitrov-redirect-import.json` рядом с этим документом.

Правило 16046 ошибочно использовало «заканчивается на» для регулярного
выражения пагинации сериалов. На старом сайте `/articles/tv-series/page/2/`
возвращал WordPress HTML/200. Оно исправлено на ограниченное правило
`^/articles/tv-series/page/[0-9]+/?$` с переходом в категорию сериалов.
HTML-сущности в названиях тегов декодируются до формирования URL, пробелы и
кириллица кодируются для корректного заголовка Location.

- Оба имени домена, HTTP и HTTP после TLS-прокси Jino используют одну таблицу.
- Известный адрес → соответствующая статья/тег/категория, сразу 301 на HTTPS Tambur.
- Учитываются регистр, завершающий слеш, процентное кодирование кириллицы.
- Входные query-параметры отбрасываются, как в исходном экспорте; параметры
  назначения (`category=filmy` / `category=serialy`) сохраняются.
- Неизвестный удалённый адрес → 410 с русским пояснением и ссылкой на сообщество.
  Это исключает оставшиеся страницы WordPress и нерелевантные 301 на главную.
- robots.txt разрешает обход; старые корневые sitemap URL ведут на sitemap Тамбура.
- HTTP-01 challenge обслуживается из существующего static volume, не перенаправляется.
- `/wp-content/uploads/…` → `https://media.tambur.pub/legacy-wp/uploads/…`.
  Кодирование и регистр имени файла сохраняются. Существование произвольных
  неиспользуемых старых файлов этим правилом не гарантируется.

Проверка PostgreSQL только чтением с timeout 5 с: все 1553 ID статей из
назначений существуют, ни один не заблокирован и не находится на модерации.
Среди 1552 импортированных статей 4 ещё содержат старую ссылку на одну
картинку с узким неразрывным пробелом в имени. Её копия в нашем S3 существует.
Новое правило сохраняет работу этих ссылок без переписывания статей.
Это проверка импортированных статей, не аудит всех файлов/почты старого хостинга.

## Архитектура и стоимость

`WordPressRedirectImporter` проверяет экспорт, явно разрешает известный вид
конфликта и отвергает новые неоднозначности/условия/посторонние назначения.
`NginxRedirectRenderer` формирует статическую конфигурацию. CLI — тонкий адаптер.
Бизнес-правила не выполняются в запросе пользователя.

На запрос: хеш-поиск nginx; при отсутствии точного совпадения — 19 ограниченных
Unicode regex и 7 правил архивов, затем правило медиа. SQL, Python/PHP, внешние
вызовы, кеш ответа и новые фоновые процессы отсутствуют. Авторизация не участвует:
это публичные старые URL; права на итоговую статью проверяет Tambur как обычно.

Таблица занимает около 1,9 МБ в текстовом виде, включает оба варианта слеша.
При 10× росте латинских адресов растут размер конфигурации/памяти и время reload,
хеш-поиск остаётся ограниченным. Рост Unicode regex увеличит стоимость промаха;
перед таким ростом нужно повторить замеры и пересмотреть нормализацию ключей.
Импорт ограничен 20 МБ / 50000 записей на файл; увеличение лимита требует оценки.
Дополнительных сервисов, БД-индексов, подписок и инфраструктурных расходов нет.

## Воспроизведение

Исходные пользовательские JSON хранятся отдельно от Git. Сгенерированная таблица
и отчёт с контрольными суммами версионируются вместе с конфигурацией.

```bash
python3 deploy/import_posletitrov_redirects.py \
  /path/to/specific-url-redirections--posletitrov.ru.json \
  /path/to/redirection-rules--posletitrov.ru.json \
  --output deploy/posletitrov_redirects_generated.conf \
  --report docs/posletitrov-redirect-import.json
python3 -m unittest discover -s tests -p 'test_posletitrov_redirects.py' -v
python3 deploy/check_posletitrov_redirects.py
```

Последняя команда запускает временный локальный nginx только на loopback,
проверяет всю таблицу и останавливает процесс. На production её не запускать.

## DNS / HTTPS — порядок включения

1. Убедиться, что новая DNS-зона содержит A-записи apex и www на сервер,
   а также необходимые MX/TXT записи почты. Не оставлять старую AAAA-запись.
2. В Jino подключить действительный сертификат с обоими именами:
   `posletitrov.ru`, `www.posletitrov.ru`. TLS завершает шлюз Jino; сертификат
   только на VPS не исправит публичный HTTPS. Проверить автопродление у Jino.
   Если выпуск до смены NS недоступен, можно импортировать действующий сертификат
   либо выпустить через DNS-01 в текущей зоне Beget. Закрытые ключи — вне Git.
3. До смены NS проверить HTTP и HTTPS через новый IP (`curl --resolve`),
   не отключая проверку сертификата. Только после успешного HTTPS менять NS.
4. После распространения DNS повторить внешние проверки обоих имён,
   обновить переезд в Яндекс Вебмастере / Google Search Console.
5. Beget-хостинг отключать после успешных проверок и сохранения резервной копии;
   продление регистрации старого домена и его сертификата сохранять.

На начальной проверке 26 октября NS ещё Beget, A=87.236.16.241.
Новый адрес 217.107.219.119 без этой конфигурации отдавал HTTP 404, а HTTPS —
сертификат другого домена. Владелец подтвердил, что SSL в Jino ещё не подключён.
До подтверждённого сертификата смену NS нельзя считать готовой.

## Откат

До изменения NS старый сайт не затронут. Для отката релиза вернуть предыдущие
версии nginx.conf и compose, пересоздать nginx с прежними mounts, проверить
`nginx -t`, перезапустить nginx и проверить HTTP 200 Tambur. Данные приложения
и миграции БД этот релиз не меняет. После переключения NS откат DNS имеет
задержку распространения; старый хостинг сохранять до проверки переключения.

# Unit Game на Тамбуре

Источник: `ugrobug/suphub`, commit `45957eecf3e65197b57ea53e14aa3cd1fb4610ba`.
Каталог `unitgame_app` перенесён в `backend/unitgame_app` без изменения всех 69
исходных файлов. Правила, интерфейс, изображения, обучение, localStorage,
ссылки для шаринга и исходный счётчик Метрики сохранены буквально.
Статистика из localStorage старого домена автоматически не переносится.

## Подключение

- `/s/unitgame` перенаправляет на `/s/unitgame/`, сохраняя query string.
- Nginx направляет `/s/unitgame/` в Django: исходные тонкие views рендерят
  меню, игру и обучение. Авторизация, SQL и API Тамбура игре не нужны.
- Приложение зарегистрировано в Django; namespace сохранён, поэтому ссылки
  меню автоматически получают новый префикс.
- Оригинальный относительный путь `../../static/unitgame_app/main.js`
  из `/s/unitgame/play/` и `/s/unitgame/onboarding/` разрешается в
  `/s/static/unitgame_app/`. Узкий nginx alias обслуживает эти модули;
  исходные абсолютные пути CSS и изображений остаются `/static/unitgame_app/`.
- В меню спецпроектов добавлена ссылка с полной загрузкой страницы, чтобы
  SvelteKit не перехватывал переход на Django-приложение.

Это интеграция существующего приложения, без рефакторинга его функций в классы:
сохранение исходной игры — прямое требование пользователя. Новая бизнес-логика
не вводится. Рабочий процесс игры полностью в браузере; сервер рендерит
ограниченный шаблон (2.6–10.7 KB HTML) и раздаёт неизменные файлы (~844 KiB
дискового пространства). При росте посещаемости в 10 раз растёт число отдач
страниц и ресурсов, а не стоимость запроса по размеру базы; постоянные
инфраструктурные расходы не меняются. Новые кеши, workers и сервисы не нужны.
Существующие политики безопасности nginx наследуются игровыми маршрутами.

## Выпуск и откат

Собрать frontend/backend по Deploy Playbook. Миграций схемы нет (в импортированном
каталоге migrations только `__init__.py`). После сборки выполнить
`python manage.py collectstatic --noinput` в backend: nginx читает ресурсы из
общего static volume. Проверить `nginx -t`, перезапустить nginx после пересоздания
контейнеров, проверить все три страницы игры, оба адреса ресурсов, главную,
реальный пост и API статуса книги. Не очищать общий кеш ради замера.

Откат: revert коммита подключения, повторить сборку и restart nginx. Схема и данные
БД не меняются; оставшиеся файлы static безопасны. Пользовательские локальные
изменения аналитики и киношаблона не входят в эту изолированную рабочую копию.

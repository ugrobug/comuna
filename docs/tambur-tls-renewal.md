# TLS tambur.pub: выпуск отдельно от Jino

## Схема

DNS зоны находится в Cloudflare. На 5 октября 2026 публичный адрес
`tambur.pub` / `www.tambur.pub` — прокси Jino, который завершает TLS и
передаёт запросы в Docker nginx на VPS. Обновление файла сертификата на VPS
само по себе не обновляет сертификат, показываемый посетителю.

Certbot на VPS выпускает сертификат через HTTP-01. Публичные одноразовые
проверочные файлы записываются в существующий Docker volume `deploy_static_data`:

- хост: `/var/lib/docker/volumes/deploy_static_data/_data`;
- nginx: `/var/www/static`;
- URL: `/.well-known/acme-challenge/<token>`.

Только этот URL исключён из перенаправлений на HTTPS и основной домен.
Nginx отдаёт существующий файл или 404 без обращения к приложению/БД,
не кеширует его и разрешает только GET/HEAD. Стоимость — проверка пути и
чтение одного маленького файла; рост числа постов и пользователей не влияет.
Ключи и сертификаты хранятся в `/etc/letsencrypt`, вне webroot и Git.

## Выпуск и проверка продления

На VPS, после проверки публичного HTTP-адреса для обоих доменов:

```bash
certbot certonly --non-interactive --webroot \
  --webroot-path /var/lib/docker/volumes/deploy_static_data/_data \
  --cert-name tambur.pub -d tambur.pub -d www.tambur.pub

certbot renew --cert-name tambur.pub --dry-run
systemctl status certbot.timer
```

Используется существующая регистрация ACME. Certbot должен сохранить
`authenticator = webroot`; установка через host nginx не нужна, так как
порт 80 занят Docker, а публичный TLS обслуживает Jino.

## Подключение в Jino

В настройках внешнего сертификата используются:

- сертификат: `/etc/letsencrypt/live/tambur.pub/cert.pem`;
- закрытый ключ: `/etc/letsencrypt/live/tambur.pub/privkey.pem`;
- цепочка CA: `/etc/letsencrypt/live/tambur.pub/chain.pem`;
- если интерфейс принимает объединённую цепочку: `fullchain.pem`.

Пакет для ручного импорта передавать только владельцу аккаунта, с правами
0700 на каталог и 0600 на файлы. Не размещать его в публичных каталогах.

**Автоматическое перевыпускание Certbot и установка в Jino — разные шаги.**
До настройки и проверки механизма импорта в Jino нельзя считать публичное
автопродление полностью работающим. Таймер Certbot не загружает сертификат
в панель хостинга. При ручном импорте после каждого перевыпуска требуется
повторная установка обновлённого сертификата в Jino.

После импорта проверить HTTPS обоих имён без отключения проверки TLS,
SAN/срок сертификата и HTTP 200 главной, реального поста и API. Контрольные
запросы — smoke-проверка, не нагрузочный тест или подтверждение p95.

## Откат

Изменение nginx откатывается возвратом предыдущей конфигурации после
`nginx -t` и перезапуском nginx. Это возвращает прежние перенаправления,
но HTTP-01 продление перестанет работать. Архивы Certbot не удалять:
они сохраняют предыдущие версии сертификата и ключа.

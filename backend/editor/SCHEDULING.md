# Отложенная публикация

Редактор отправляет `publish_at` как ISO 8601 с часовым поясом. Дата отображается
в часовом поясе браузера. Отсутствующее время или `null` означает немедленную
публикацию; сохранение черновика само по себе публикацию не запускает.

При планировании используются существующее поле `Post.publish_at`,
`is_pending=True` и маркер `raw_data.scheduled_publication`. Такие посты скрыты
публичными API и доступны владельцу через редактор и вкладку «Черновики и
отложенные». Черновик может сохранять дату, но не получает маркер расписания.

## Серверный обработчик

В production Compose добавлен сервис `scheduled-posts`:

```bash
python manage.py publish_scheduled_posts --loop
```

В обычном режиме он проверяет очередь каждую секунду. Закрытый браузер автора
не влияет на публикацию. После простоя обработчик публикует просроченную очередь.
Разовый запуск без `--loop` удобен для проверки или восстановления.

Обработчик блокирует строку поста, снимает `is_pending` и маркер расписания,
ставит дату выхода в `created_at`, обновляет данные сообщества и создаёт
уведомления. Редактор использует ту же блокировку для переноса, отмены и удаления.
Повторный запуск не публикует один пост дважды. Заблокированные и удалённые посты
пропускаются. После публикации пересобирается материализованная главная лента.
Существующий HTTP-кеш списков может обновиться позже самой страницы поста.

Новые миграции не требуются. Для включения функции на сервере нужен деплой
frontend, backend и нового сервиса из Compose.
